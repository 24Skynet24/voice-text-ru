# План проверки

Автоматические тесты (`pytest`) закрывают логику, которая не требует микрофона:
сегментацию речи, вставку текста без дублирования, работу с файлами, разбор
горячих клавиш и пересчёт частоты дискретизации.

Сценарии из §40 технического задания требуют живого микрофона и реальной
речи, поэтому проверяются вручную по списку ниже. Отмечайте результат и
прикладывайте выдержку из журнала (`Справка → Открыть журнал работы`).

## Автоматические тесты

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

| Файл | Что проверяет | Пункт ТЗ |
|---|---|---|
| `test_worker.py` | Разбиение речи на фразы, отсутствие дублирования, обработка остатка при остановке | §10, §15, §22, §33 |
| `test_transcript_inserter.py` | Вставка с позиции курсора, замена черновика, история отмены | §3, §15, §16 |
| `test_document.py` | UTF-8, cp1251, BOM, переводы строк, атомарная запись | §24, §25 |
| `test_vad.py` | Определение пауз, устойчивость к фоновому шуму | §10 |
| `test_postprocess.py` | Фильтрация «галлюцинаций» модели, склейка фрагментов | §12 |
| `test_resample.py` | Пересчёт 44.1/48 кГц → 16 кГц без наложения спектров | §17 |
| `test_hotkey.py` | Разбор сочетаний клавиш | §7 |

## Ручные сценарии

### Тест 1 — базовая запись (§40.1)

1. Запустить приложение, создать `тест1.txt`.
2. Нажать «● Запись», произнести по-русски две–три фразы с паузами.
3. Нажать «■ Остановить».

Ожидается: текст появился в документе, файл на диске содержит тот же текст,
строка состояния показывает время последнего сохранения.

### Тест 2 — запись в фоне (§40.2)

1. Начать запись, переключиться в браузер, говорить 30 секунд.
2. Вернуться в приложение, остановить запись.

Ожидается: распознавание не прерывалось, текст за время работы в браузере
попал в документ, в журнале нет сообщений об ошибках.

### Тест 3 — свёрнутое окно (§40.3)

1. Начать запись, свернуть окно, говорить 30 секунд, развернуть окно.

Ожидается: текст на месте, индикатор уровня продолжал работать.

### Тест 4 — глобальная горячая клавиша (§40.4)

1. Открыть документ, переключиться в другое приложение.
2. Нажать `Ctrl+Shift+Space`, говорить, нажать сочетание ещё раз.

Ожидается: запись началась и остановилась без переключения в приложение.
Дополнительно: закрыть документ и нажать сочетание — должно появиться
предупреждение «Сначала создайте или откройте документ».

### Тест 5 — существующий документ (§40.5)

1. Открыть `.txt` с несколькими абзацами.
2. Поставить курсор в середину, начать запись, говорить, остановить.

Ожидается: текст вставлен **с позиции курсора**, а не в конец; существующий
текст не изменён.

### Тест 6 — автосохранение (§40.6)

1. Начать запись, говорить несколько минут.
2. Не останавливая запись, открыть файл в другой программе (например, в
   Блокноте) и убедиться, что текст обновляется.
3. Завершить процесс приложения через диспетчер задач.

Ожидается: в файле сохранены все фразы, кроме, возможно, последней
незавершённой.

### Тест 7 — длительная запись (§40.7)

Провести непрерывный сеанс 30–60 минут, наблюдая за процессом в диспетчере задач.

Ожидается:
* потребление памяти стабильно (буфер ограничен, ТЗ §22);
* задержка не растёт со временем;
* нет повторов текста;
* автосохранение продолжает работать.

### Тест 8 — отключение микрофона (§40.8)

1. Начать запись с USB-микрофона.
2. Физически отключить его.

Ожидается: понятное сообщение об ошибке, запись остановлена, приложение не
закрылось аварийно, уже распознанный текст сохранён.

### Тест 9 — закрытие во время записи (§40.9)

1. Начать запись, говорить, закрыть окно, не останавливая запись.

Ожидается: окно закрывается не мгновенно (идёт дообработка), последняя фраза
попадает в файл, в журнале есть записи об остановке потоков и освобождении
микрофона.

## Проверка сборки

1. `powershell -ExecutionPolicy Bypass -File build\build.ps1`
2. Выполнить проверку установки — она не открывает окно и сразу показывает,
   загрузились ли нативные библиотеки и модель:

   ```powershell
   & "dist\VoiceTextRU\Voice Text RU.exe" --selftest путь\к\записи.wav
   ```

   Отчёт: `%LOCALAPPDATA%\VoiceTextRU\selftest.txt`. Строк со словом «ОШИБКА»
   быть не должно, а распознанный текст должен соответствовать записи.
3. Запустить `dist\VoiceTextRU\Voice Text RU.exe` на машине **без** Python
   и пройти тест 1 и тест 4.

Подходящий файл для проверки можно записать любым диктофоном либо получить
из синтезатора речи Windows (моно, 16 кГц).
